# 0383. A file's leading comments are its JS's

Status: Accepted. Extends [0018](0018-print-with-oxc.md).

Case: N ([0262](0262-when-rust-and-js-disagree.md)): comments, which
nothing runs.

## Context

A file moved to Rust keeps what it starts with, react.dev's license:

```rust
/*
 * Copyright (c) Meta Platforms, Inc. and affiliates.
 * ..
 */
```

Its JS had rust-js's line alone, `// Generated by rust-js from ..`: the
license the file it replaced had was gone from the file the app ships.

## Decision

**The comments a Rust file starts with, `//` and `/* */`, up to its first
doc comment, attribute or item, are its JS's, after rust-js's line, as
written.**

```js
// Generated by rust-js from src/components/ExternalLink.rs. Do not edit.

/*
 * Copyright (c) Meta Platforms, Inc. and affiliates.
 * ..
 */
```

- **A doc comment is its item's or its module's**: `///`, `//!`, `/**`
  and `/*!` end them, as Rust reads them; `////`, `/***` and `/**/` are
  plain, as Rust reads them too.
- **A block comment Rust nests**, `/* a /* b */ c */`, which JS ends at its
  first `*/`, ends them.
- A module's `.d.ts` has them too, after the same line.
- A `/** .. */` license, a TypeScript file's, is `/* .. */` in Rust, where
  `/**` documents the item after it: its JS is `/* .. */`.
