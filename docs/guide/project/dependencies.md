# Dependencies: crates and npm packages

An app depends on three kinds of thing, each declared where its ecosystem
declares it:

| What | Declared in | Its JS |
| --- | --- | --- |
| The crates rust-js ships: `js`, `webapi`, `node`, `react`, `next` | `Cargo.toml`, and `package.json` | none: a call is the JS API's own call |
| A crate from crates.io | `Cargo.toml` | compiled by rust-js, into `rust-js/crates/` |
| An npm package | `package.json`, and a binding in your Rust | the package's own |

## The crates rust-js ships

Each binds a JavaScript API, typed as TypeScript types it. A binding crate
has no JS of its own: a call to one of its functions is the call you'd
write in JS, and nothing else.

| In Rust | Cargo package | npm package | Binds |
| --- | --- | --- | --- |
| `js` | `rust-js-builtins` | `@rust-js/builtins` | JS's language: promises, errors, `RegExp`, JSON, timers, typed arrays |
| `webapi` | `rust-js-webapi` | `@rust-js/webapi` | the browser: the DOM, `fetch`, events, storage |
| `node` | `rust-js-node` | `@rust-js/node` | Node.js's modules: `fs`, `path`, `process`, `http` |
| `react` | `rust-js-react` | `@rust-js/react` | React and React DOM, and `jsx!` |
| `next` | `rust-js-next` | `@rust-js/next` | Next.js's components and hooks |

What's in each is [The crates rust-js ships](../libraries/README.md).

### Add one

Name it twice, by the same version: in `Cargo.toml`, as the Rust name you
`use`, and in `package.json`, where Cargo finds it.

```toml
[dependencies]
js = { package = "rust-js-builtins", version = "~0.0.2" }
node = { package = "rust-js-node", version = "~0.0.1" }
webapi = { package = "rust-js-webapi", version = "~0.0.3" }
```

```json
{
  "dependencies": {
    "@rust-js/builtins": "0.0.2",
    "@rust-js/node": "0.0.1",
    "@rust-js/webapi": "0.0.3"
  }
}
```

Your package manager's lockfile pins them. Each time `rust-js build` runs,
it finds each installed package that has a crate and tells Cargo where it
is: a `[patch.crates-io]` in `.cargo/config.toml`, between `# rust-js:
begin` and `# rust-js: end` ([ADR 0118](../../decisions/0118-bindings-on-npm-only.md)). Don't edit it, and don't commit
it. A crate installed twice, at two versions, is refused, naming who asked
for each.

### Use one

```rust
use js::JsError;
use node::{BufferEncoding, fs, process};

pub fn read_index() -> Result<String, &'static JsError> {
    let root = process::cwd() + "/content";
    fs::read_file_sync(&(root + "/index.md"), BufferEncoding::Utf8)
}
```

```js
import { readFileSync } from "fs";
import { $try } from "@rust-js/runtime";

export function readIndex() {
  const root = process.cwd() + "/content";
  return $try(() => readFileSync(root + "/index.md", "utf8"));
}
```

```rust
use js::encode_uri_component;
use webapi::document;

pub fn set_title(title: &str) {
    document.set_title(title);
}

pub fn search_link(query: &str) -> String {
    format!("/search?q={}", encode_uri_component(query))
}
```

```js
export function setTitle(title) {
  document.title = title;
}

export function searchLink(query) {
  return `/search?q=${encodeURIComponent(query)}`;
}
```

A global is a global, and a module's export is an `import` of it: install
the npm package the JS imports, as you would for JS. An app that uses
`react` has `react` and `react-dom` in its `package.json`; one that uses
`next` has `next`.

### React's version

The `react` crate binds React as of its latest release, for whichever
React from 18.0 on your app has installed: `rust-js build` reads
`node_modules/react`. A hook or prop a later React added than yours is a
compile error, with a note that says which React it needs ([ADR 0043](../../decisions/0043-react-versions.md)).

## Crates from crates.io

Add a crate as in any Rust project. rust-js compiles it, where it can,
and its JS is your app's, committed, in `rust-js/crates/<name>-<version>/`:

```toml
[dependencies]
heck = "=0.5.0"
```

```rust
use heck::ToKebabCase;

pub fn slug(title: &str) -> String {
    title.to_kebab_case()
}
```

```js
import { strToKebabCase } from "../rust-js/crates/heck-0.5.0/src/kebab.js";

export function slug(title) {
  return strToKebabCase.toKebabCase(title);
}
```

```text
my-app/
├─ src/lib.js
└─ rust-js/crates/heck-0.5.0/src/kebab.js   // Generated by rust-js from src/kebab.rs. Do not edit.
```

- **Only what your modules import is written.** A crate's module no module
  of yours reaches gets no file.
- **The version is the directory's name.** An upgrade writes the new
  version's JS and removes the old one's.
- **`rust-js build --check` checks it** with the rest of your JS, so CI
  needs no compile.
- **A crate rust-js can't compile is its types alone.** You can use its
  types; a call into it is refused, saying why it wasn't compiled (ADR
  0415):

  ```
  error: rust-js does not support calling `once_cell::unsync::OnceCell::<T>::new` yet
   --> src/lib.rs:4:16
    |
  4 |     let cell = OnceCell::new();
    |                ^^^^^^^^^^^^^^^
    |
    = note: its crate is its types alone: rust-js couldn't compile it (ADR 0415): rust-js does not support calling `std::thread::current` yet
  ```

Which popular crates compile and run is
[Crates from crates.io](../libraries/crates-io.md), measured in
[the crate corpus](../../crate-corpus.md).

### serde

serde, serde_derive and serde_json are read by rust-js as rustc builds
them, not compiled: your derives and calls become JS that reads and writes
JSON directly. So are hashbrown's and indexmap's maps, which are JS `Map`s,
and memchr.

```toml
[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
pub struct Contact {
    pub name: String,
    pub email: String,
}

pub fn to_json(contact: &Contact) -> String {
    serde_json::to_string(contact).unwrap_or_default()
}
```

```js
import { $toJson } from "@rust-js/runtime";

function contactSerialize_serialize(contact, json) {
  json.beginObject();
  json.key("name");
  json.string(contact.name);
  json.key("email");
  json.string(contact.email);
  json.endObject();
}

export function toJson(contact) {
  const result = $toJson(contact, contactSerialize_serialize, false);
  return result.TAG === "Ok" ? result._0 : "";
}
```

The same `Contact` is your native server's: put it in a crate both depend
on ([Building](building.md#a-cargo-workspace)).

## npm packages

Install the package as you would for JS, and bind what you use: a
function whose `link_name` is the module, a `#`, and the export.

```rust
pub struct Options {
    pub particle_count: u32,
    pub spread: u32,
}

#[cfg_attr(rust_js, rust_js::link_name = "canvas-confetti#default")]
pub fn confetti(options: &Options) {
    unreachable!()
}

pub fn celebrate() {
    confetti(&Options {
        particle_count: 100,
        spread: 70,
    });
}
```

```js
import confetti from "canvas-confetti";

export function celebrate() {
  confetti({ particleCount: 100, spread: 70 });
}
```

- **Before the `#` is the module**, written into the `import` as it is:
  `nanoid`, `@codemirror/state`, `node:path`, or `./local.js`, relative to
  the crate root's JS file.
- **After it, the export**: a name, `default`, or `*` for the module
  itself.
- **The binding's body never runs.** It's `unreachable!()`, and the binding
  writes no JS.

The whole binding form, its types, methods and classes, is
[Write bindings for JavaScript APIs](../interop/bindings.md).

## A library on npm

A rust-js library is one npm package: its crate, and the JS and `.d.ts`
its author's `rust-js build` wrote beside the Rust. Its `package.json`
says which crate it has:

```json
{
  "name": "@acme/greet",
  "version": "1.0.0",
  "main": "src/lib.js",
  "types": "src/lib.d.ts",
  "rust-js": { "crate": "acme-greet" }
}
```

A rust-js app depends on it in both files, and imports it by the
package's name; your rust-js compiles its crate again, into the package
([ADR 0414](../../decisions/0414-a-library-on-npm-as-rescripts-are.md)):

```toml
[dependencies]
greet = { package = "acme-greet", version = "1" }
```

```js
// the app's src/lib.js
import { greet } from "@acme/greet";
```

What the crate's root module exports is imported by the package's name,
where its `main`, or its `exports`' `"."`, is that module's JS; another
module's item by its file, `@acme/greet/src/util.js`.

A JS app imports the author's JS as it imports any package. See
[Emitting modules](modules.md#libraries) for how to publish one.

### A package's entry

A crate whose directory has a `package.json`, a workspace's member too,
may have an entry of its own, as React's `packages/react/index.js` is,
and its root re-export what the entry does:

```js
// packages/react/index.js, the package's "main"
export {Children, createElement} from './src/ReactClient';
```

```rust excerpt
// packages/react/react.rs, the crate's root
pub use react_client::{CHILDREN, create_element};
```

An item the entry re-exports is imported by the package's name, as
upstream writes it, where the Rust names it through the crate's root and
Node finds the package from the consumer
([ADR 1008](../../decisions/1008-what-a-packages-entry-re-exports-is-imported-by-its-name.md)):

```js
// of `use react_isomorphic::CHILDREN;`
import { Children } from "react";
// of `use react_isomorphic::react_client::CHILDREN;`
import { Children } from "../../react/src/ReactClient.js";
```

- **A root that only re-exports what the entry does writes no JS**: a
  `react.rs` of `mod`s and `pub use`s the entry re-exports from the same
  modules is no `react.js`, the entry already its package's.
- **The path you write decides**, in each module: through the crate's
  root, by the package's name; through the item's module, by its module's
  file.
- **Re-exports alone**: `export { .. } from` and `export * from` of the
  crate's modules. An entry with code of its own imports nothing by the
  package's name. An item its module only re-exports of another is
  imported by its own module's file.
- **The default entry**: of `exports["."]`'s conditions, the `import` or
  `default` one, or both where they name one file; what another condition,
  `react-server`'s, gives is the host's to choose
  ([the semantics](../semantics.md), 31).
- **JS, not Flow**: an entry with types in it is refused, naming it. Keep
  its types in a `.d.ts` beside it, `index.d.ts`; an `@flow` header over
  plain JS is fine.

## Versions

- **rust-js's own packages are one version**: `@rust-js/build`,
  `@rust-js/native`, `@rust-js/runtime` and `@rust-js/std`. `rust-js build`
  refuses a runtime of another version than its compiler.
- **Each binding crate has its own version**, the same in Cargo and on
  npm: `rust-js-react` 0.0.4 is `@rust-js/react` 0.0.4. Name it `~0.0.4` in
  `Cargo.toml` and `0.0.4` in `package.json`.
- **The Rust release is rust-js's**, 1.99.0 today, not yours: rust-js runs
  with the rustc it was built with, and Cargo runs that toolchain for your
  build.
