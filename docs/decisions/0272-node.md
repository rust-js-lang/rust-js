# 0272. Node's modules are a crate of their own, typed as @types/node

Status: Accepted. Follows [0024](0024-web-crate.md) and
[0192](0192-next.md). Amended by [0443](0443-a-value-a-caller-may-leave-out-is-an-option.md): an optional argument is an `Option` of the one function, where it was a `_with_` form of its own.

Case: N ([0262](0262-when-rust-and-js-disagree.md)).

## Context

react.dev's errors page reads its Markdown in Next.js's `getStaticProps`,
which runs in Node:

```tsx
const fs = require('fs');
const rootDir = process.cwd() + '/src/content/errors';
mdx = fs.readFileSync(rootDir + '/' + path + '.md', 'utf8');
```

The builtins crate is JS's language, and webapi the browser's, from
WebIDL. Node's modules are in neither, and a port's own bindings for them
would hide that rust-js lacks them.

## Decision

**The `node` crate, `rust-js-node`, is Node's modules, hand-written as the
builtins crate is, typed as `@types/node` types them, one binding at a time
as ports need them.** Its first:

- `fs::read_file_sync(path, encoding)` is `readFileSync(path, encoding)`,
  imported from `fs`, a `Result` of what it throws (ADR 0035): a missing
  file is routine, as the page's `catch` has it.
- `process::cwd()` is `process.cwd()`, `process` a global.
- `BufferEncoding` is `@types/node`'s, each variant its string, `"utf8"`.

`node/build.sh` builds its metadata, as `webapi/build.sh` does.

## Why

- **It's the JS a person writes in Node**: an import of `fs`'s, which
  Next.js leaves out of a page's client bundle with `getStaticProps`.
- **`@types/node` is what a TypeScript program has**, as the react crate
  follows `@types/react`.
- **Hand-written, not generated**: `@types/node` is TypeScript, overloads
  and all, not WebIDL; a generator is worth it when ports need much of it.
- **It's tested**: a compiler test reads a file, a missing one, and the
  directory it runs in.

## Alternatives

- **Generate it from `@types/node`**, as webapi is from WebIDL: all of
  Node, but a TypeScript reader's work before the port moves.
- **The port's own bindings**: what rust-js lacks would stay lacking.

## Amendment: `http`'s request and response

`node::http` (2026-10-10) binds `IncomingMessage` and `ServerResponse`,
what a server's handler is given, and what Next.js's Pages Router gives
`getServerSideProps` and an API route: a request's method, URL, headers
and version, and a response's status, headers, `write` and `end`. Each is
an instance, its members bound by their names, so no module is imported.
Their streams' events aren't bound yet. A bindings test serves a fetch
with a handler of them.

## Amendment: hand-written, module by module, by one set of rules

Generating it was weighed again and set aside (the user's choice,
2026-10-10): hand-written, with `node/coverage.txt` (ADR 0351) saying
what's done and what's left. Hand-written bindings drift, as ReScript's
Node bindings do (their `stat` calls `lstat`), so each module is bound by
webapi's rules and a bindings test runs each binding against Node's own:

- **A module's value is its named import**, `path#join`, also of an
  `export =` object's members, as Node's ESM gives them; a constant or an
  object of one is a `static`, `path::sep`, `path::win32`.
- **An optional parameter is a `_with_` form**, `basename_with_suffix`,
  named as webapi names one (ADR 0024); a rest parameter a slice,
  `#[rust_js::variadic]` (ADR 0221).
- **An interface given is a struct of `Option`s with `Default`**,
  `FormatInputPathObject<'a>`; one returned, of owned fields,
  `ParsedPath`; an object with methods, a handle, `PlatformPath`.

`path` (2026-10-10) is the first bound whole, 19 of 19.

`url` (2026-10-10): 17 of 24. Its WHATWG classes, `URL`,
`URLSearchParams` and `URLPattern`'s, are the globals, so the crate
re-exports webapi's (it now depends on webapi) and binds the rest: file
URLs, domains, `resolve`, `format` of a `URL`. Its legacy `parse` and
`Url` wait for `querystring`, `fileURLToPathBuffer` for `Buffer`, and
`urlToHttpOptions` for `http`'s `ClientRequestArgs`.

`querystring` (2026-10-10): 10 of 10, its values an untagged enum of a
text or a list, and `url`'s legacy `parse` and `format`, 22 of 24: a
parsed `Url<Q>` of its query's type, `UrlWithStringQuery` its text's and
`UrlWithParsedQuery` a `ParsedUrlQuery`'s. A parameter whose absence is
nothing, `stringify`'s object, is required.

`process` (2026-10-10): 64 of 77, each a function of the global, its
properties read by `get process.x` and written by `set process.x` (ADR
0024's amendment). Its listeners, stdio, IPC `channel` and `send`, and
`mainModule` wait for `events`, `stream`, `child_process` and `module`.
The test runs the program in Node itself, as Bun's `process` isn't Node's.

`buffer` (2026-10-10): 17 of 17, but TypeScript's own types (`x`, as
react's coverage marks them, ADR 0347's amendment). `Buffer` derefs to the
js crate's `Uint8Array`, its numbers each of their Rust type as the js
crate's are (ADR 0283), `read_uint16_be` a `u16`; the global's functions
are its associated ones, `Buffer::from_with_str`. Of Node's aliases,
`readUInt8` and `readUint8`, the second is bound, one spell for one job.
`Blob` and `File` are the globals, webapi's.

`crypto`, `stream` and `util`'s text classes (2026-11-01), what React's
server stream config for Node imports: `crypto.createHash(algorithm)`, a
`Hash` updated with text or bytes and digested as a
`BinaryToTextEncoding`'s text; `stream.Writable`'s `write` of text or
bytes, `end` and `destroy`; and `util.TextEncoder` and `TextDecoder`,
webapi's types, each made by `util`'s own constructor, `util::text_encoder::new()`
being `new TextEncoder()` of `import { TextEncoder } from "util"`: a
host may have no global `TextEncoder`, as React's Flight tests' Jest
environment hasn't, where `util`'s is still there. A Writable's events and
its other members wait for a port that needs them. The test hashes and
writes to a Writable in Node itself.

## Amended (2026-11-01): a Writable's events (rd459)

React's renderToPipeableStream listens to its destination:
`destination.on('drain', createDrainHandler(destination, request))`, and
a cancel handler on `'error'` and `'close'`. **A `stream::Writable` is an
emitter, `EventEmitterExt`'s `on` and the rest, of `event::Drain`
(`dyn Fn()`), `event::Error` (`dyn Fn(&JsError)`) and `event::Close`
(`dyn Fn()`), each listener of its event's own type**, as `Process`'s are.
React reuses one handler of no parameters for `'error'` and `'close'`. A
listener takes what its event gives, though, and the port adapts at the
call, `(error) => cancel()`, rather than `on` taking listeners of fewer
parameters (the user's decision). Held by `test/node-bindings.test.ts`
("a Writable's drain, error and close are listened to").

## Amended (2026-11-01): a Readable (rd462)

React's prerenderToNodeStream's prelude is `new Readable({ read() {
startFlowing(request, writable); } })`, written to by a writable that
pushes to it, `readable.push(chunk)`, and ends it, `readable.push(null)`.
**`stream::Readable` is `readable::new(Some(&ReadableOptions { read:
Some(&|size| ..), .. }))`, `new stream.Readable(options)`. Its `push`
takes any value, as @types/node's `push(chunk: any)` does, `None` its
`null`, and gives whether it takes more; its `destroy` takes any error.**
`read` is lent, as a dictionary's callback is, and JS keeps it. Held by
`test/node-bindings.test.ts` ("a Readable is pushed to by its read").

## Amended (2026-11-02): a Readable's events (rd601)

React's Flight client for Node reads its stream, `stream.on('data', chunk
=> ..)`, `stream.on('error', error => ..)` and `stream.on('end', onEnd)`,
in each of react-server-dom's five packages. **A `stream::Readable` is an
emitter, `EventEmitterExt`'s `on` and the rest, of each event @types/node
types its `on` of: `event::Data` (`dyn Fn(Option<&Unknown>)`, its `chunk:
any`), `event::End`, `event::Error` (`dyn Fn(&JsError)`), `event::Close`,
`event::Pause`, `event::Readable` and `event::Resume` (each `dyn Fn()`)**,
as a Writable's are (rd459). Each event is a name of its own (ADR 0361),
`"data"`, `"end"`, `"pause"`, `"readable"`, `"resume"` added to the
crate's. Held by `test/node-bindings.test.ts` ("a Readable's data, end,
error, close, pause, resume and readable are listened to"), run in Node.

## Amended (2026-11-02): a Duplex, a Readable and a Writable both (rd588)

React's Flight server for Node takes a `debugChannel: Readable | Writable
| Duplex | WebSocket`, read from and written to. @types/node types
`stream.Duplex` as `interface Duplex extends Readable, Writable`, and
Node's `Duplex` extends `Readable`, a `Writable`'s methods mixed in.
**`stream::Duplex` derefs to `Readable`, as its prototype extends it, and
is `AsRef<Writable>`, `duplex.as_ref()`, as it's one too: each the object
itself, its `as_ref` bound `link_name = "this"`. It's an emitter of both's
events, data, end, pause, readable and resume a Readable's, drain and
finish a Writable's, and close, error, pipe and unpipe; a Writable emits
`event::Finish`, `event::Pipe` and `event::Unpipe` (`dyn Fn(&Readable)`)
too, as @types/node types them.** Rust's `Deref` is to one type, so the
other side is the conversion std has for "this is also a": a `Duplex`
given where a `&Writable` is, `send(duplex.as_ref(), ..)`, is
`send(duplex, ..)`. A second method form of the Writable side's own,
`duplex.write(..)`, would be a second way to write each.

A std trait's method whose impl a binding crate declares, which no std
lowering knows, `<Duplex as AsRef<Writable>>::as_ref`, is that binding,
as an index signature's `Index::index` is (ADR 1011): it was called
through a dictionary, which rust-js refused ("implementation evidence").

Busboy, which React's Node reply decoder reads, is an npm package's
binding, so a crate of its own (ADR 0118), `bindings/busboy` beside
react-in-rust's `bindings/art`: its `Busboy` derefs to `Writable`.

Held by `test/node-bindings.test.ts` ("a Duplex is read from and written
to, and emits both's events"), run in Node, and the mutation
`binding-impl-by-dictionary` (`lower/mir/dispatch.ts`).

## Amended (2026-11-01): `Buffer.from` of a `Uint8Array` (rd465)

React's noop server reads a chunk as `Buffer.from(buffer).toString('utf8')`,
a copy of a `Uint8Array`'s bytes. `Buffer::from` took only `&[u8]`.
**`Buffer::from<D: IntoBytes>(data)` is @types/node's `from(data: Uint8Array
| readonly number[])`, a sealed union of `&[u8]`, `&[u8; N]`, `&Uint8Array`
and `&Buffer`.** It's a type parameter, not `impl IntoBytes`, so a test of
the host names it, `js::is_function(Buffer::from::<&[u8]>)`. Held by
`test/node-bindings.test.ts` ("node's buffers are made, read and written", `copied.equals(&bytes)`).

## Amendment (2026-11-01): `async_hooks` (rd492)

React's Fizz server keeps the request rendering in an
`AsyncLocalStorage`, `requestStorage.run(request, ..)` and `getStore()`,
and Flight's debug build tracks each promise awaited by `createHook({
init, before, promiseResolve, destroy }).enable()`, `executionAsyncId()`
and `AsyncResource.prototype.asyncId.call(promise)`. The node crate bound
none of `async_hooks`, so the ports bound them locally. Case A
([0262](0262-when-rust-and-js-disagree.md)): they're Node's own, so
nothing differs.

**`node::async_hooks` is @types/node's**, ten of its eleven exports:
`execution_async_id`, `execution_async_resource`, `trigger_async_id`;
`create_hook(&HookCallbacks)` of `Option<&'static dyn Fn ..>` callbacks,
kept by Node for as long as the hook is, its `AsyncHook`'s `enable` and
`disable`; `AsyncResource`, made of a type and `f64 | &AsyncResourceOptions`
(`IntoAsyncResourceTrigger`), with `async_resource::async_id_of(value)`,
the prototype's `asyncId` called of any value, a `Result` as it throws of
what Node doesn't know; and `AsyncLocalStorage<T>`, `get_store`, `run` and
`exit` of a closure, `enter_with` and `disable`. `asyncWrapProviders`, a
namespace of constants, isn't bound yet. Held by
`test/node-async-hooks.test.ts`, run in Node, whose hooks Bun lacks: a
store read inside a `run`, inside an `exit`, after an `await` in it and
outside, a hook counting promises, and a proxy's id an `Err`; and
`node/coverage.txt`, blessed. Bindings only: no compiler change, so no
mutation.

### Its store is owned (rd497)

`run(store, ..)` and `enter_with(store)` took a `&'static T`, so React's
Fizz, whose request is an `Rc<Request>`, cast one to keep in it. Node
keeps the store for the code it runs and each resource made, as long as
they last: the storage owns it. **`run` and `enter_with` take a `T`**,
`storage.run(Rc::clone(&request), || ..)`, `request` in JS; `get_store`
still lends it, `Option<&'static T>`. Held by
`test/node-async-hooks.test.ts`, of an `AsyncLocalStorage<Rc<Request>>`.
