# 0415. A crate of crates.io's is compiled into the app, where it can be

Status: Accepted. Amends [0101](0101-cargo-workspace-wrapper.md), which
left a registry's crate to rustc, and [0414](0414-a-library-on-npm-as-rescripts-are.md),
whose crates rust-js compiles are a path's.

Case: N ([0262](0262-when-rust-and-js-disagree.md)): which crates are
compiled, and where their JS goes, not what a program means.

## Context

The north star is Rust across the stack, with Scala.js's library support,
and Rust's libraries are crates.io's. ADR 0101 left a crate of crates.io's,
or of git's, to rustc: an app could use its types, and a derive's code,
which is its own (ADR 0186), but a call into it was refused, as no JS of it
was written. rust-js compiles some of them now: of the 16 crates measured
in `docs/crate-corpus.md`, strum, thiserror, bitflags and chrono.

A crate of crates.io's isn't the app's: its Rust is in Cargo's registry,
`~/.cargo/registry/src`, a cache every project on the machine shares and
Cargo has as read-only, so its JS can't go beside its Rust, as an npm
package's does (ADR 0414). And its JS must be there before the app's
bundler runs, in CI too, where `rust-js build --check` writes nothing.

## Decision

**rust-js compiles each crate of crates.io's or git's an app uses, where
it can, and its JS is the app's, committed, in
`rust-js/crates/<name>-<version>/`. One rust-js can't compile is its types
alone, as rustc builds it, and a call into it is refused, saying why.**

```
my-app/
  Cargo.toml        greet = "0.1"
  src/lib.rs        greet::hello("Ada")
  src/lib.js        import { hello } from "../rust-js/crates/greet-0.1.0/src/lib.js";
  rust-js/crates/greet-0.1.0/src/lib.js   // Generated by rust-js from src/lib.rs. Do not edit.
```

- **Tried, not required.** The tooling gives rust-js the app's own crates,
  which must compile, `RUST_JS_CRATES`, and its crates of crates.io's or
  git's, `RUST_JS_DEPENDENCIES`, both from `cargo metadata`. rust-js tries
  each of these in a process of its own. Refused, rustc checks it, its
  types alone, as without rust-js, and why is written beside its metadata,
  `lib<crate>-<hash>.rust-js-refused`: a call into it says so.

  ```
  error: rust-js does not support calling `addr::address` yet
    = note: `addr` is its types alone: rust-js couldn't compile it (ADR 0415):
            rust-js does not support addressable memory yet: a pointer's address
  ```

- **serde's crates are rustc's**, as rust-js reads them (ADR 0077): serde,
  serde_core and serde_json are never tried.
- **What the app imports is written, no more.** A crate's module is written
  where a module of the app's imports it, or one such module does: serde_json's
  own crates, `itoa` and `ryu`, which rust-js may compile, aren't written,
  as no module of the app's imports them.
- **Committed, and checked, as the app's own JS is**: `rust-js build
  --check` compares it, so CI's build needs no compile, and an upgrade of
  a crate is a diff to read. Its header names its Rust from its crate's
  directory (ADR 0414).
- **Its version is its directory's name**: an upgrade writes the new
  version's, and the old one's goes, its directories too, as a crate no
  longer used does: the build's record of what it wrote has the app's
  crates of crates.io's as one.
- **It's quiet** (ADR 0414): Cargo caps a registry crate's lints, and its
  build checks (ADR 0117) aren't run.

## Why

- **Every crate is compiled by the app's own rust-js** (ADRs 0100, 0414),
  so a crate's JS is never held to another rust-js.
- **No app that builds today stops building**: a crate rust-js can't
  compile is what it was, its types, and the error comes where its code is
  called, with why.
- **Readable, and in the app**: what the app runs is in its repository, as
  Cargo's `vendor` keeps sources, and reviewed as its own JS is.
- **It's tested** (`test/registry-crates.test.ts`), a git repository
  standing in for crates.io, which Cargo has alike: a crate compiled,
  committed, imported from there, run, and checked; one upgraded, the new
  version's JS written and the old one's gone; one rust-js refuses, its
  types used, and a call into it refused, saying why. The serde workspace
  test holds that serde's crates aren't tried.

## Consequences

- **A first build tries each crate of crates.io's**, in a process of its
  own: slower once; Cargo keeps each crate's build after.
- **An app's repository has `rust-js/crates/`** once it calls into a crate
  of crates.io's that rust-js compiles.
- **What rust-js can compile of crates.io grows** with `docs/crate-corpus.md`:
  raw memory stops 7 of its 16 crates.
