# A shipped memchr searches bytes

Status: Draft. A candidate under [the shipped-crate contract](shipped-crates.md).

Case: C ([0262](../0262-when-rust-and-js-disagree.md)) for indices, search
order and iterator behavior; A for replacing an unobservable SIMD or
pointer-based implementation with byte operations; D outside the
qualified API.

## Decision

**Implement the supported memchr API over the compiler's existing byte
slice representation.** No conversion to a JS string and no new byte
container representation merely for this crate.

The initial qualification covers `memchr`, `memchr2`, `memchr3`, their
reverse searches and their iterator forms. A byte offset is relative to
the supplied slice, including a sub-slice with a nonzero backing offset.
Bytes are all values from 0 through 255, regardless of whether they form
UTF-8 text. A no-match result uses the existing `Option` representation.

Iterators retain front/back state and preserve the selected Rust version's
clone, exhaustion and size-hint behavior. They use the iterator owner's
protocol and ownership rules, not a second iterator implementation
convention. The memory engine's acceleration is not observable behavior;
the indices and order it returns are.

`memmem`, finder values, and any other unqualified API remain compiler
refusals until separately covered in this same API matrix. Supporting
memchr does not by itself make regex compile.

## Acceptance

Compare all qualified operations against native Rust on empty slices,
single bytes, every possible byte value, repeated needles, equal needles
in two/three-byte searches, absent matches, and sub-slices. Exercise
matches at both ends and adjacent positions.

For iterators, alternate forward/backward reads, clone after partial
consumption, and read after exhaustion. Generated byte arrays supply
broader differential coverage. Mutations return backing-array offsets,
skip the final byte, mishandle repeated needles or share clone positions.

Benchmark short and large slices and inspect output. Use typed-array
operations only where they operate on the existing representation with
the required semantics; any necessary adaptation must be explicit and
must not add a hidden full-array copy on every search.

Qualification of versions, features and source identity, and all failure
behavior, follows the common shipped-crate contract.
