# 0207. A crate's `.d.ts` is printed by TypeScript

Status: Accepted. Amends [0196](0196-typescript-declarations.md); uses
[0206](0206-typescript-module.md). Amended by
[0381](0381-the-apps-prettier-lays-it-out.md): where the app's Prettier has
a config for a `.d.ts`, it lays it out.

Case: N ([0262](0262-when-rust-and-js-disagree.md)).

## Context

rust-js wrote a module's `.d.ts` as strings (ADR 0196): its own guess at
how TypeScript is written, its parentheses, its quoting, its `Omit<..>`,
which only TypeScript reading it afterwards checked. The JS is printed by
oxc from a tree (ADR 0018); TypeScript should be too, by TypeScript.

## Decision

**A module's declarations are @rust-js/typescript's model, JSON, and
TypeScript prints them: rust-js runs the module where the crate is, by
Node, once for all of a build's modules, which builds each as
TypeScript's syntax tree with TypeScript's factory, and prints it with
TypeScript's printer.** Where the crate is: its `Cargo.toml`'s directory,
or, for a file compiled alone with none above it, the file's own
(`Settings::dir`); run nowhere, it failed as "`node` can't be run".

```ts
// Generated by rust-js from src/components/Button.rs. Do not edit.

import type { ReactNode } from "react";

export interface ButtonProps<C> {
    children: C;
    active?: boolean;
}

export function Button<C>(props: ButtonProps<C>): ReactNode;

export default Button;
```

- **It's TypeScript's style**: four spaces, as its printer writes, and a
  blank line between declarations.
- **Erasable syntax only**, as TypeScript's `erasableSyntaxOnly` says: the
  model has no `enum`, a unit-only enum being a union of its names, no
  parameter property, no `import =`, and the module refuses a namespace
  holding values but a `declare`d one's.
- **A crate without @rust-js/typescript is told to add it**: its build
  fails, saying `npm install --save-dev @rust-js/typescript`. `RUST_JS_NODE`
  names a Node other than `node`.

## Why

- **It's TypeScript's**: what rust-js decides is what's declared, the
  model; how it's written in TypeScript is TypeScript's.
- **It's tested**: the declarations test checks each declaration as
  TypeScript prints it, then TypeScript that uses them against them,
  the declarations checked too, `skipLibCheck` off; a crate without the
  module is refused; and the module's own test checks what it prints is
  erasable, by TypeScript with `erasableSyntaxOnly`.

## Costs

- **A build with `declarations = true` runs Node and TypeScript's
  process**, a second or so the first time.
- **A crate with declarations needs @rust-js/typescript installed**, and
  TypeScript 7 with it.

## Amendment: a name that's an identifier is as it's written (#582)

Case ([0262](0262-when-rust-and-js-disagree.md)): none. A quoted key and
an identifier name the same property, so it's how the `.d.ts` reads.

A member's name was written as it is only where it was an ASCII
identifier, `/^[A-Za-z_$][A-Za-z0-9_$]*$/`, and quoted otherwise, so a
field named `名` was `"\u540D": number`, escaped by TypeScript's printer.
**A member's name is an identifier where TypeScript's scanner reads it as
one, `isIdentifierText`, a non-ASCII one too, `名𠀀é: number`, and quoted
where it isn't, `"aria-label"`, `"1st"`, `""`** (`propertyName`,
typescript/index.js). The scanner is TypeScript's own rule of what an
identifier is, so the module keeps no second one. Held by
test/typescript.test.ts ("print writes a name that's an identifier as it
is") and test/settings.test.ts's non-ASCII names, whose key is now the
name itself. Its mutations are none: scripts/mutations.ts mutates src/'s
files.
