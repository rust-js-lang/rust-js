# Tests at a glance

As of 2026-10-30, `main` at `120772e2`; times are CI's, check run 41022723550.

| Suite | Size | What it proves | Time |
|---|---|---|---|
| `bun run test` | 3,736 tests in 165 files | Everything below except mutations, rustc, fuzz and the nightly's files | 11–13 min on 2 machines: each one's corpus parts, 8.5–9.6 min, then its browser files |
| ↳ the nightly's files (`nightly` in `scripts/shard.ts`, ADR 1030) | 19 files, ~170 tests: tidy's stages, iterator forms, fuzz's seeds, the release's packaging, the coverage ratchets, React's releases, the editor's check, the harness, build history, limitations | What each says; a mutation that names one still runs it | ~1,000 s of CPU, run only by the nightly's suite, `--nightly` |
| ↳ corpus | 1,576 Rust programs (`test/corpus/*.rs`) | Each one's JS prints what native Rust prints, and matches its snapshot; built as a library too, each push only the 120 marked `library-differs`, the nightly every one (ADR 0360) | about half the suite |
| ↳ the other 163 files | ~2,360 tests | Lowering rules, diagnostics, bindings (js, webapi, React, Node), hosts (Vite, Next, cargo), `rust-js test` by each runner (node, bun, Vitest, Jest; ADR 1076), React's ported modules against their snapshots, docs, architecture | the rest |
| `cargo test` | 57 unit tests | Tidy's passes and decisions | <1 min |
| Mutations | ~7,700 (`scripts/mutations/`) | Each rule has a test that fails without it | a check runs only the changed ones: ~10 min on up to 16 machines; built up to 32 to a compiler (ADR 1031) |
| rustc's suite | 3,762 run-pass tests, 1,493 of them out of scope | rustc's own programs run the same as JS | a check runs a sample in 1 min; all of them take ~2 h 45 min |
| Generated programs | 600 random programs a night | Programs no one wrote | in the nightly |
| Tidy's stages (`test/tidy-stages.test.ts`) | 9 corpus cases in the nightly's suite; every case a night, each at 16 stage ends | Each of tidy's stages leaves JS that runs as native Rust does (ADR 0659) | in the nightly: its suite runs the 9, and every case on 6 machines |
| Iterator forms (`test/iterator-forms.test.ts`) | 45 corpus cases in the nightly's suite; every case a night, built with std's iterator structs alone (`--std-iterators`) | That build runs as native Rust does, but the cases `differs` lists, which only shrinks (ADR 0908) | in the nightly: its suite runs the 45, and every case on 2 machines |

- **A check** (each push to `main`, which runs to its end; `bun run ci:check` of another branch) runs everything except the full rustc suite, fuzz and the nightly's files, in parallel: about **15 min**.
- **The nightly** runs the suite with its own files, every mutation, the 600 programs, every corpus case after each of tidy's stages, every case with std's iterator structs alone, the crate corpus and React's port: **~2–3.5 h**, a red night opening an issue, `Nightly red: <date>`.
- **The crate corpus** (`bun scripts/crate-corpus.ts --check`, the nightly's `crates` job, ADR 1067) compiles each of `docs/crate-corpus.md`'s 22 crates, at the exact release its row names, with every crate it uses at the release its lock, `scripts/crate-corpus/<name>.lock`, names (`--locked`), and runs its probe beside native Rust, failing where a crate does worse than its row says; a row marked with an open issue, `runs (refused: #467)`, holds while the crate does just that. All 22 took 4.4 min on the Mac from an empty `target/crate-corpus` (2026-11-03), Cargo's jobs at their default again: its largest rust-js process is 436 MB, since regex-syntax's crash was fixed (#511).
- **React's port** (`bun scripts/react-in-rust.ts`, ADR 1067), react-in-rust at `ports/react-in-rust.pin`: `regen`, the nightly's `port` job, compiles its workspace to JS in one `rust-js build` (ADR 1068) and fails on a compile error or any file that differs from what the pin committed, 8 min cold on the Mac (475 s, 2026-11-02, against 36 min one crate at a time) and 2 s warm (40 min one crate at a time); on CI, 28 min one crate at a time with the release build cached (nightly 41417626908), not yet timed since; `check`, the **React port** workflow, of a push that changes `builtins/`, `webapi/`, `node/` or `react/` alone, `cargo check`s its workspace natively, no compiler built: 3 s on the Mac with the port fetched, 23 s on CI (run 41417596826).
- **The nightly, here**: `bun run nightly` runs each of its jobs on the Mac's cores, all of it in 77 minutes on the M3 Max (2026-10-30, `3dfa326a1`, 8,047 of 8,047 mutations caught in 65 of them), the suite with its own files, tidy's stages and the iterator forms of every case, the day's 600 programs, rustc's tests, the examples, the WASM compiler and every mutation; `bun run nightly <job>..` some of them.
- **On the Mac**, each command has a timeout of about twice its usual time, and runs on all the cores: the suite in parallel groups took about 3 minutes (2026-10-30), the corpus in 8 parts 90 s (AGENTS.md).

To recount: the test totals are the `Ran N tests` lines in a check's `test (k/2)` logs. The corpus is `ls test/corpus/*.rs | wc -l`, the mutations are `grep -rc 'name:' scripts/mutations`, and the rustc counts are the line counts of `test/rustc-*.txt`.
