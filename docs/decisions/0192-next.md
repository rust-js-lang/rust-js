# 0192. A Next.js app's routes and components in Rust, beside its JS

Status: Accepted. Extends [0041](0041-react.md), [0101](0101-cargo-workspace-wrapper.md)
and [0105](0105-create.md).

## Context

rust-js's apps are Vite's (ADR 0041): Rust components that compile to the
JSX a person writes, which Vite serves with Fast Refresh. Next.js 16, the
App Router, is the other way a React app is made, and asks more of a
module than a component does:

- **A route is a file, `app/page.jsx`, whose default export is its page**,
  where rust-js wrote named exports only.
- **A component is a Server Component** unless its file's first statement is
  `"use client";`, as one with state or events must be, where rust-js wrote
  no directives.
- **Turbopack, its bundler, runs a webpack loader on a file, which gives one
  module back**: it can't write a crate's other modules, `emitFile` is
  unsupported, and a crate is compiled whole, by Cargo (ADR 0101).
- **Its components take many optional props**, `next/image`'s twenty, where
  `jsx!` gave a component every field of its props struct, named.

## Decision

**A Next.js app's Rust is a Cargo package whose modules are the app's
files, `app/page.rs` beside `app/layout.js`, each compiled to its JS beside
it, `app/page.jsx`, as the Vite plugin's Cargo builds do. `rust-js-next dev`
and `rust-js-next build` are `next dev` and `next build`, the Rust compiled
first, and again on each save.**

```
app/
  layout.js       JS, as create-next-app writes it
  page.rs     ─►  page.jsx      export default Home;
  counter.rs  ─►  counter.jsx   "use client";
  about/
    page.rs   ─►  page.jsx
```

- **`js::export_default!(Home);` is `export default Home;`**, of a function
  of the module's own, which keeps its name for the crate's other modules.
  A `const _` names it, `use Home as _;`, so a plain rustc checks it's there, a generic function too, which `let _ = Home;` couldn't name without its types.
- **`js::directive!("use client");` is the module's directive**, its first
  statement, before its imports: a client component's. A module without
  one is a Server Component, as a JS one is.
- **The crate is the app's**, `[lib] path = "app/page.rs"`, and a route
  below it is a module, `mod about { pub mod page; }`, which Rust finds at
  `app/about/page.rs`.
- **`rust-js-next` is `@rust-js/next-plugin`'s**: the Vite plugin's Cargo
  build, `cargo check` with rust-js as its wrapper, a watcher of the
  crate's Rust, and `next` as its child. A compile error is rustc's, in the
  terminal: `dev` goes on with the last JS that compiled, `build` stops.
- **What Cargo writes is `node_modules/.cache/rust-js/target`**, unless
  `CARGO_TARGET_DIR` says otherwise: Turbopack watches an app's files,
  every directory's but `node_modules`' and `.next`'s, as measured on
  Linux, so a `target/` there, each save's `cargo check` rewriting many of
  its files, would be as many changes to it, and as many of inotify's
  watches.
- **A file the JS replaces is written in place**, as an editor saves one,
  its old bytes kept by a copy until all are written: one renamed over it,
  as rust-js's publication did, was missing a moment, which Turbopack took
  for deleted, and its importer for broken.
- **Next.js's API is the `next` crate's**, `@rust-js/next`: `next/image`'s
  `Image`, `next/link`'s `Link`, and `next/navigation`'s hooks, `not_found`
  and `redirect`, bound as any JS is (ADR 0039).
- **A component's named props take the rest from `{..base}`, Rust's struct
  update**: `<Image src="/next.svg" alt="" width={Some(100)}
  {..Default::default()} />`, a binding's props a `Default` struct of
  `Option`s, `None` left out of the JSX, as `undefined` is. Its base is
  evaluated last, as Rust's is. JSX's `{...base}` with named props is still
  an error: JSX's would override them.
- **A component's default import is named after its binding**,
  `import Image from "next/image"` of `fn Image`, as a `static`'s is, where
  it was the module's, `image`, which JSX takes for an element.
- **An `Element`'s default is React's empty node, `undefined`**, so a props
  struct with children derives `Default`; children not given aren't written.
- **`bun create @rust-js my-app --template next`** makes the Next.js
  example's app, create-next-app's JavaScript App Router template with its
  page in Rust, as the default, `vite`, makes the Vite one's.

## Why

- **It's Next.js's own layout**: a route is where Next.js looks for one,
  and the JS beside it is what Turbopack, Fast Refresh and Next.js's
  rendering see, a module of the app's. Nothing of Next.js is configured.
- **It's the Vite plugin's build**, already tested: Cargo's, the JS beside
  the Rust, committed (ADR 0041). Only what starts it is new.
- **It's tested as an app is used**: `test/next.test.ts` builds the example
  with a client component and a route below it, and checks the page Next.js
  renders; then `next dev` in a browser, the counter counting, a save kept
  as a Fast Refresh, an error and its fix, and `next/link` going home
  without a load. `test/create.test.ts` makes the template's app and checks
  it with a plain `cargo check`, its crates the npm packages.

## Alternatives

- **A Turbopack loader for `.rs`**, `import { Counter } from "./counter.rs"`:
  what a loader gives is one module, where a crate's `cargo check` writes
  all of them, and it would compile a crate for each file imported.
- **Every module a client component**: hooks would just work, but a Server
  Component, Next.js's default, couldn't be written in Rust.

## Costs

- **Two of `next`'s modules are bound, and of them what an app uses
  first**: `next/font`, `next/headers`, `next/server`, and Server Actions
  aren't, nor is a Server Component's `async`.
- **A compile error isn't in the browser's overlay**, only the terminal's.
- **An editor's rust-analyzer writes `target/`**, which Turbopack does
  watch, unless it's given the same `CARGO_TARGET_DIR`.
- **A prop is `Some(..)`**, `width={Some(100)}`, where JSX's is the number.
- **The props of a component were in its struct's order**, not as
  written: they're as written since ADR 0203.
